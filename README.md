# 灵感 inspiration

**当前版本：v0.4.10**。作品工具、作品管理、预览上下文和模型／上下文／详情成为共用固定顶栏的独立页面，已保存的作品数据与生成 API 不迁移。较早的 `v0.1.0` Release 继续保留。

A writing-first fiction workbench for DeepSeek Harness, with AI drafting, precise selection polishing, and author-approved inline edits.

面向中长篇小说的 **AI 起草 → 作者手改 → 选段润色 → 预览并确认入稿** 工作台。

这是独立的 DSH 插件，不依赖、不修改参考插件，也不接管现有小说目录。首版面向本机单作者；不做多 Agent 自动写整本书。

## 安装与兼容性

安装 **v0.4.10** 请选择 GitHub Release 的预构建包或固定版本标签。源码及可运行浏览器产物也可从 [开发分支 `feat/writing-constraints`](https://github.com/EliasRookie66/dsh-inspiration/tree/feat/writing-constraints) 获取。不要直接将含写作约束的作品数据交给更早的 `v0.1.0` 读取。

- 当前支持声明：DSH **0.2.2-rc.3**，Node.js **>=22**。其他 DSH 版本尚未验证，不建议跳过兼容检查。
- 在目标 DSH Web／Desktop 的「插件管理 → 添加插件」中使用：

  ```text
  github:EliasRookie66/dsh-inspiration#v0.4.10
  ```

- 也可从 [v0.4.10 Release](https://github.com/EliasRookie66/dsh-inspiration/releases/tag/v0.4.10) 下载 [预构建安装包](https://github.com/EliasRookie66/dsh-inspiration/releases/download/v0.4.10/ycx-dsh-inspiration-0.4.10.tgz)，通过宿主支持的包安装入口使用。同一页面提供 `SHA256SUMS` 校验文件。
- 源码与可运行 JavaScript 均位于仓库根目录，没有安装期构建脚本。是否需要刷新或重新启动，以宿主安装结果为准；先保存当前工作。
- 本项目尚未发布到 npm；仓库名与包标识 `@ycx/dsh-inspiration` 不必相同。

## 开始写作

1. 在 DSH 侧栏打开 **灵感**，进入「作品工具」新建作品和章节。
2. 在作品设置填故事前提、全书大纲与文风。把需要坚持的世界观、人物、时间线、伏笔和规则写入设定卡。
3. 设定卡标为「已确认」才会进入上下文；用起止章节控制它在哪个时点生效。固定卡片与规则完整保留，装不下时明确报错，不静默截掉硬约束。
4. 选择「起草本章」或「按需重写本章」，填写要求，可在「预览上下文」查看本次参考资料。默认沿用 DSH 当前模型，也可在「模型／上下文／详情」单独选择写作模型，不需要另一套 API 密钥。
5. 点击「生成」后，在正文中审阅结果。起草整章需点勾才替换，按需重写可逐处采纳或拒绝，旧正文保留在版本历史中。
6. 手改正文会自动保存。选区润色前需先保存，选中原文后从浮层明确发起；来源版本变化后，不会强制覆盖新稿。
7. 已有摘要和旧提案继续保留；正文、标题或本章提纲变更会使旧摘要失效，生成时不会把失效摘要当作已确认事实。

## 写作区与顶部搭档

正文、写作约束、设定卡、作品设定和版本历史共用固定顶部工具栏，页面内容在下方独立滚动。图标悬停显示原功能名称，键盘和屏幕阅读器仍有可访问名称。切页时作品与章节下拉保持在顶栏。「作品工具 → 作品管理 → 预览上下文 → 模型／上下文／详情」按顺序固定，并分别切换到独立页面，不再展开正文区或弹出管理面板。页面中不再重复显示产品名称或标语；正文、约束、设定正文和历史文字采用相同的内容字号，标题和辅助文字保留各自层级。

**「章节列表」显示当前章的序号与标题**，点开原生下拉切换，仍先处理自动保存及未保存确认。如果等待同一笔保存期间改变选择，只执行最后一次有效选择。「改标题」按需展开编辑。正文页的「生成」仍在固定顶栏；任务、要求和结果选择留在正文区域。四个工具页面不受专注模式折叠影响；从工具页面切换书或章节时保留所在页面。

「专注写作」隐藏任务和扩展详情，保留固定的页面导航、作品和章节选择。点「显示工具栏」恢复写作操作，不重置当前章、要求、模型草稿和任务；批准结果、取消生成、保存和失败恢复仍可用。窄窗口中顶栏可换行，内容仍可以独立滚动。

「写作任务」只提供「起草本章」和「按需重写本章」；选区润色使用选中文字后的浮层，独立于章节任务和要求。正文底部不再显示章节摘要编辑区，已保存摘要不清除，旧摘要提案仍从「生成结果」审阅。生成的结果不会自动写入书稿。

差异采用轻量行内/逐行展示，新文本在前、原文在后；不再用重边框卡片包装每处修改。真实替换显示确切旧文字；纯插入则展示**插入位置的原文上下文**并明确标注此处新增，不把空替换范围误称为缺失原文。仅换行、Tab 或空格的改动有可见提示，不再显示空白绿条。用于对照的上下文不会进入实际替换范围，精确的原始偏移与确认逻辑不变。

写作界面不再显示「本章计划」、正文操作说明、选区计数提示和「章节状态」下拉框；已有计划和状态数据仍保留，原有计划仍可作为上下文使用。顶部不再固定留出整条 64px 空白，标题行依据宿主窗口按钮的实际横向安全区避让，整体更靠上。

## 选中文字后的原位润色

先保存正文，在正文编辑框中用鼠标或键盘选中一段文字，自动出现：

- **AI 润色**：使用默认的保留原意、改善表达要求润色选区。
- **按需润色**：填写具体要求后润色选区，例如「更口语化，但保留人物克制的语气」。

选中文字只弹出操作，不自动调用模型。明确点击后使用当前所选写作模型发起一次润色调用；流式结果在原选区位置显示，**绿色建议在上，红色原文在下**；等待、流式生成和完成后始终保留原文对照。无输出时绿色区域仅显示一次「正在润色...」，有输出后由实际文字替换占位，不再重复标题或等待说明。原文来自不可变来源，前后未选中的正文保持不变。未完成或失败的流式片段不能采纳，不能当作已保存正文。

确认控件统一采用 Cursor 风格的紧凑细线 SVG 勾/叉按钮，跟随主题颜色，不使用 emoji。悬停提示和无障碍名称分别说明采纳与拒绝。

完整候选返回后，点 **勾图标** 才把这一段真正替换并保存；点 **叉图标** 则保留原文。完成决定后返回正常正文编辑。点击勾／叉当下记录当前审阅段落的屏幕位置与外层滚动位置；确认成功且仍为同一来源/章节/结果时，按新挂载文本框的实际排版测量原选区位置，恢复到当前审阅段落附近。刷新后或重新选中的有效历史结果也从点击当下记录，不依赖发起任务时的会话锚点；无需重新生成。字号/面板变化导致旧坐标超出当前视口时钳到可见范围。源码、实际确认回调与位置计算已测试，但实际页面滚动像素仍需人工确认。浮层润色不会切换当前「写作任务」，也不会改写任务栏里的要求。

未保存稿、恢复稿、冲突、模型偏好未应用或任务繁忙时会阻止发起/确认，并说明原因，不悄悄保存或覆盖本地编辑。换章、修改原稿或重新选择其他文字后，旧浮层/旧点击不能针对新位置继续执行。重复句子、Emoji 与 CRLF 换行使用保存原文的 UTF-16 精确范围，不按文本首次出现位置替换。

## 按需重写本章与逐处确认

在 **写作任务 → 按需重写本章** 选择此模式，先保存当前章节，再输入具体要求，例如：

> 对话：太过生硬，且对话比较少。请增加自然、有效的对话，保留人物关系和原情节，不要为了增加对话而重复信息。

点击生成后会自动顺序调用当前所选写作模型 **两次**：先给出简短分析与优化方案，再针对性改写完整的**当前章节**。无需选中文字；不是批量重写整部作品。两次调用都可能计费，均会发送该阶段提示中纳入的小说内容，途中可取消，不自动重试收费调用。

完成后，有效的待审阅修改自动出现在正文对应位置，不再显示「普通正文编辑器」说明，也没有「打开预览 / 查看已保存正文」模式切换。交互参考 VSCode 行内建议，但不会通过 Tab 自动批准或在后台写稿；改动处直接标出新文字并提供原文对照：

- **勾图标 采纳并保存此处修改**：只把这一处真正写入原稿，其他待确认部分仍只是预览；每次采纳保留原正文历史并使旧摘要失效。
- **叉图标 拒绝此处修改**：这一处恢复显示原文，不改正文。
- **一键批准**：一次批准当前可见生成结果的所有待审阅修改，已拒绝的部分保留原文；不是批准全书或其他结果。全文润色批量批准只做一次原子保存并留一份批准前历史，失败不写入半个结果。普通生成/选区润色则批准当前完整结果。
- **拒绝剩余修改**：丢弃尚未确认的部分，已采纳并保存的内容不撤销。
- 已接受的文字和已拒绝修改的原文立即恢复为普通文本，仅待处理片段保留差异标记；全部处理完后回到可输入的正常正文。需要继续手写时，可先处理或拒绝剩余修改。普通「保存」不会把 AI 建议整体写入，只有勾图标或「一键批准」才采纳 AI 修改。

如果生成时仍在手写，完成后不会挡住未保存稿；先处理本地编辑、恢复稿或冲突，来源仍有效时会自动原位显示建议。过期或无效结果只显示简短行内异常提示，不覆盖新原稿，也不提供强制打开旧来源的按钮。未确认改动、分析和每处决定随候选持久化；重新打开后可继续审阅。无修改结果直接保留可编辑正文，可用现有收起操作结束该结果，不创建虚假的确认项。

安全限制：分析上限 2,000 字符；生成前为分析封装保留 5,000 上下文字符，配置预算需至少 6,000 且足以容纳完整原章、作者要求及固定设定。不够时明确拒绝，不悄悄截去原章；可在作品设置提高预算。差异最多 256 处，计算达到上限时明确提示采用较粗的替换块，仍完整保留全部优化结果。单次局部采纳若超过正文 200,000 字符上限会原子拒绝，可先采纳减少篇幅的修改。正文历史仍只保留最新 30 份，重要修改前建议导出 JSON 备份。

## 连续 Markdown 写作约束（v0.4.3）

「写作约束」是同一个连续文档。直接点击文字定位光标，就能输入、跨类别选择和复制粘贴，无须打开某条规则的输入框。以 `**重点**` 为例：光标在这个片段内时能编辑原来的星号，移开后原地显示为粗体。拖选跨多条规则时不把选中区全部展开成语法，避免文字不断挪动。示例：

```markdown
- 环境
    - **随人物感知展开。** 优先写人物此刻会注意到的事物。
- 对话
    - [x] 根据人物身份、关系和当前目的组织对话。
    - [ ] 这是一条暂时停用的条件。
```

- 也支持 `## 类别` 加普通列表。普通规则默认启用，`[x]` 启用，`[ ]` 停用；规则的续文用六个空格缩进。类别不是固定枚举。在类别行末按 Enter 会缩进并插入 `- [x] - `；从已有的 `- [x] -` 或 `- [ ] -` 规则按 Enter 会以相同缩进续写 `- [x] - `，不改变上一条的状态。未填写正文的前缀不会保存为规则。规则内 Shift+Enter 只插入续行；Tab／Shift+Tab 对当前项或选中行调整缩进。先按 Esc 再按 Tab 可把键盘焦点移出编辑器。
- 「添加类别」左侧的「编写规则」打开说明弹窗，包含缩进、启停、规则内项目符号的示例，以及保存和恢复行为。
- 「显示 Markdown 语法」只关闭同一编辑器里的排版，按钮随之变为「隐藏 Markdown 语法」；再次点击恢复排版。两种显示不重置光标、选区或撤销。恢复未完成稿时，会在同一个编辑器显示原文并定位到末尾；切换板块后回到未改变的同一稿件，会恢复选区和滚动位置。
- 新增类别／规则会选中对应的占位文字。将光标放进某条规则后可以用当前规则的启停、删除按钮；工具栏删除有确认。可以直接编辑或删除文档中的部分条目；暂时清空非空文档不会删除全部约束，最后一条须用删除按钮确认。工具栏改动可在编辑器中撤销；重新打开作品不保留撤销历史。
- 支持常见写作格式：强调、标题、删除线、引用、列表、行内代码和围栏代码。安全链接标签仅排版，不从编辑器直接跳转；HTML 和图片语法保持文本，不执行脚本或加载图片。未完整复刻 Typora 的表格、数学公式等能力。
- 服务器仍只保存有序约束数组。精确编辑范围保留未变部分的换行与排版，区分重复规则，撤销恢复相应的 UUID、启停和文字。重开时，外层标题／列表拼写可能从已保存的数组重建；外层格式变化不会向服务器写入。
- 有效内容约在停笔 1 秒后自动保存。未完成稿仍在原处可编辑，按原文进入本地恢复并阻止生成；其他有效字段可独立保存。每本书最多 64 条，类别 80／内容 4000 个 UTF-16 单位。原文上限为 2,000,000 个 UTF-16 单位；此上限不保证浏览器的恢复存储空间足够。本地恢复不等同于备份。

## 安静的自动保存（v0.3.0）

停止输入约1秒，或结束字段编辑后，自动保存有效的手动正文、标题、作品设置、写作约束及设定卡。旧版提纲和摘要仍保留，已有本地恢复稿也可照常处理。后台保存不锁住输入，不逐次弹出成功或“有未保存更改”提示；仍可显式立即保存和使用Ctrl/Cmd+S。

- 仅保存手动稿。AI生成的正文、摘要、选段和逐处修订仍是候选，必须作者明确确认后才入稿；不自动调用模型，不改变模型偏好。
- 请求期间继续输入或撤销到旧值，最新本地内容仍须保留，完成后再串行保存；不会用旧响应覆盖新输入。字段暂时为空或不合法时留在本地，不把无效约束过滤成删除操作，其他有效字段仍可保存。
- 每次写入沿用书籍版本CAS。网络失败或外部版本冲突后暂停，保留恢复稿，需显式重试/核对，不在后台盲目重放。正在进行的写入与结果不明确的请求也计入离页保护。
- 切换作品/章节先尝试保存，仍有未完成或失败的更改才沿用防丢稿确认。放弃只影响待保存的本地部分，已自动保存的内容不会回滚；正文沿用既有版本历史与保留上限。
- 本地恢复稿仍不等于服务端备份。关闭页面前如仍有未完成写入，请等待或保留/下载恢复稿；JSON备份另行导出。新卡创建使用稳定UUID和只新建操作，响应丢失后核对同一身份，不猜测匹配或重复创建。

## 持久化写作约束（v0.2.0）

在当前作品的 **「写作约束」** 页管理环境、对话、神态、动作、心理、外貌、情节、节奏、视角和文风等条件。类别可自由输入，不限于建议项；同一类别可有多条约束。可新增、编辑、启用/停用、删除及上下调整顺序。

- **按作品独立保存**：不是所有作品共用的全局规则。界面修改先作为本地草稿，有效完整的条件在停笔后自动持久化，也可显式立即保存；不完整条目保留在本地，不会被当作删除操作发送。尚未保存成功的修改会阻止发起生成，换书/章、冲突与恢复沿用草稿保护。新书不自动填入示例条件。
- **每次实际生成调用都携带**：已保存且启用的条件以完整固定 JSON 块加入起草、续写、选区润色、摘要，以及全文润色的分析/改写两个阶段。不会按相关度筛掉，也不会只把条件存进界面。停用项的类别与内容不进入模型提示。
- **不静默截断**：每本书最多64条；类别1–80个UTF-16单位、条件内容1–4000个UTF-16单位，停用条目也需有效文字。所有启用项完整计入上下文预算，超出预算会在模型调用前明确拒绝；可调整条件或提高作品预算，而不是悄悄忽略末尾条件。上下文预览报告显示启用与停用处理。
- **任务开始时固定快照**：运行中修改约束不改变已经发起的任务，全文润色两阶段保持同一组条件；修改对下一次新任务生效。不增加额外模型调用，但额外条件会增加提示长度及潜在费用。
- **不扩大任务权限**：书级条件仍受固定设定、选区边界与摘要事实来源限制，不会授权外部操作或自动入稿。模型可能不完全遵守自然语言条件，仍须作者审阅。
- **备份与旧版兼容**：JSON导出/导入保留条件；Markdown导出仍仅是稿件，不包含这些设置。旧书没有该字段仍可正常读取，不在读取时自动改写。新建或保存带约束字段的书籍不能交给旧版v0.1.0读取，升级前建议保留JSON备份，不要直接降级。

## 写作模型选择

在独立的 **「模型／上下文／详情」** 页面，可以选择：

- **沿用 DSH 默认模型**：每次开始生成时读取当时的全局默认模型。
- **灵感专用模型**：从当前已配置、已启用的服务商与其公布的模型中选择；支持时可选择推理档位，也可沿用该服务商的默认档位。

修改下拉框后，点 **「应用到灵感」** 明确保存；仅改变灵感插件的设置，不修改 DSH 全局默认模型，也不改书稿。偏好按当前 profile 的灵感插件独立保存，切换作品和重新打开后仍保留；不是每本作品单独的设定。

未应用、目录载入中或保存失败时不能开始新生成，避免界面选择与实际调用不一致。另一页面修改模型后，会要求重新载入模型设置，保留本地选择与书稿。失效的已保存路由不会偷偷换成其他模型，可明确切回「沿用默认」或选择新的可用模型。

**正在运行的任务继续使用启动时锁定的模型**；模型选择只影响之后发起的起草、按需重写本章及选区润色任务；兼容 API 发起的旧模式同样采用最新配置。任务区域显示实际调用模型。目录与能力查询不会生成正文；点击生成后才调用所选服务商，费用与数据处理以该服务商规则为准。模型目录公开的选项不保证当前账号配额或网络一定可用。

## 作品管理

在顶部作品选择器选中目标作品，再点旁边的 **「作品管理」**。同名作品会附带章节数与编号片段，管理页显示完整作品编号和审阅版本，避免删错。作品设定页只显示已保存名称，改名统一在作品管理。

- **重命名**：修改已保存的作品名称；正文、设定、章节与历史不变。
- **删除作品**：先处理未保存改动和本地恢复稿；建议从「前往作品工具备份」跳转到唯一的导出入口。完整输入管理页显示的已保存书名，才可确认永久删除。生成未结束时不能删除；可先取消生成并等待其结束。
- 删除覆盖该作品全部章节、设定卡、候选、历史和插件任务记录；仅清理这本书在当前页面的本地草稿/任务缓存，不清空其他作品。已有下载备份、其他设备或页面的缓存以及 DSH 模型会话日志不随之删除。
- 删除后可选择其他作品或新建/导入作品；最后一本删除后显示空书库入口。删除已成功但后续列表刷新失败，会单独提示，不把成功误报成删除失败。
- 并发改名/改稿后旧确认失效，必须重新核对；网络中断而未收到明确删除回执时保留本地副本，先刷新核对，不盲目重试。
- 存储故障可能留下「残留数据待清理」：作品已从书库移除并禁止读取/写入，但**不代表所有数据已擦除**。插件下次加载自动重试，列表持续提示待清理数量。KV 后端不提供整单元删除，清理完成后可以保留不含书稿的空存储单元。

## 长篇上下文

- 「预览上下文」读取当前章节和任务的最新已保存参考资料，显示完整提示词、纳入项、遗漏项和警告，不调用模型。「按需重写本章」预览第一阶段提示词；第二阶段要等分析结果生成。「模型／上下文／详情」只显示模型设置、任务状态和选中结果保存的生成报告，不重复本次预览。
- 只纳入已确认、且落在当前章节范围内的设定卡；不引入未来章节正文/摘要。
- 故事前提、大纲和本章提纲明确标注为计划，不冒充已发生事实。**大纲本身可能包含未来计划**，本机制并不阻止模型看到创作计划。
- 既往章节使用有效摘要和近期正文节选；可选背景允许截短/省略，但报告会标明。
- 本次作者要求、精确选段、固定设定和规则不会静默裁剪；摘要任务需要完整当前章正文，超预算需调整预算或手动整理。
- 默认预算 18,000，范围 1,000–60,000，计数单位为 **JavaScript UTF-16 字符数**，不是精确 token，也不是模型窗口容量保证。设置过小甚至容不下基础写作约定。上下文最终还受所选模型限制。
- 前文有修订历史时会保守提醒复核后文；这不是自动语义推理，更不会自动重写后续章节。

## 正文与数据安全

- 每次保存校验作品 revision。并发页面/工具写入造成冲突时拒绝覆盖；本地稿应保留后再人工合并。
- 所有候选采纳都同时比对来源章节 revision 和完整原文；选区从 textarea 规范化后的值映射回保存原文的 UTF-16 坐标，并验证原文匹配。选区外字节不会被领域逻辑重新排版。
- 手工保存、采纳和恢复旧稿都会保留旧正文；每章最多 30 份历史。恢复也是一次新修订，不是无痕撤销。
- 生成过程可取消，取消信号传给模型适配器；已送出的请求可能仍计费，服务商是否及时停止由适配器/上游决定。取消、模型错误或输出截断不产生可采纳候选。
- 每书最多 1 个生成任务，全局最多 3 个；15 分钟超时。正文/候选单项最多 200,000 字符，摘要最多 40,000；普通输出请求上限 8,192 token、摘要 2,048 token，并非保证能写满这些长度。
- 每本书（含历史/候选）最多 32 MiB JSON。可先导出备份，再使用「清理已处理候选及旧历史」：移除已采纳/拒绝候选，历史只保留各章最新 5 份；未处理候选不丢弃。若未处理稿占满容量，应先明确拒绝不需要的稿再清理。
- JSON 导入严格校验，并分配全新作品/章节/卡片/历史编号；旧候选清空，原作品不覆盖。Markdown 导出只含书名与各章正文，不附设定、历史和候选。
- 浏览器草稿恢复属于临时保护，**不能代替明确保存或导出备份**；清除浏览器数据会丢失未保存草稿。建议定期导出 JSON。

## 持久化与隐私

通过当前 DSH 的 JSON 存储后端持久化，不写用户现有小说目录。每书独立的 single-layout KV 单元 `ycx_moxu_book_<uuid_underscore>`，索引和近 40 个任务元数据在 `ycx_moxu_index`；模型偏好在独立单元 `ycx_inspiration_settings` 的 `settings/model` 记录中（不写入作品 JSON）；通过后端原子写入，调用方串行化修改。损坏的单书/索引读取报错，不用空作品覆盖。未被索引提交的孤立文件不会主动删除。

生成前先持久化任务来源；每次模型请求还有独立的 DSH 会话 `inspiration-<jobId>`，记录完整模型可见输入、响应流和调用状态。会话日志使用 DSH 自己的持久化生命周期。重启后未完成任务标记失败，不自动重新收费生成。

名称已统一为「灵感 / inspiration」。为保留更名前的数据，底层 KV 单元和浏览器草稿仍使用最初的 `ycx_moxu_` / `ycx-moxu:` 私有键；它们不是界面名称，不需要手工迁移。

**点击生成，会将上下文中实际纳入的小说内容发给当前所选写作模型对应的服务商（沿用默认时为 DSH 默认服务商）。** 本地书稿、草稿缓存、任务记录和 DSH 会话日志均可能含完整正文；它们不是本插件加密的。卸载不自动删除这些数据。日志保留遵循 DSH 的会话管理机制，清理作品历史不同时清除会话日志。

HTTP 接口仅允许当前 Host 的精确 Host、loopback socket、JSON 与专用请求头，且必须通过 DSH `connection.admit` 认证为当前 browserPeer（API Peer 即使拥有 owner 权限也不视作作者界面）。普通 Web 请求的 Origin 须精确匹配；Desktop 原生代理会校验页面来源后去掉 Origin 与 Sec-Fetch-Site，只有两者同时缺省且通过同一浏览器认证才兼容。`Origin: null`、跨站、未认证或伪造 cookie 均拒绝，没有 CORS 放行。**这不是本机恶意程序/其他高权限插件的隔离边界**，不支持公网、多用户或跨主机部署。工具接口禁止采纳/恢复，但不能声称拥有通用 shell/文件权限的 Agent 绝对无法绕过；正常工作流必须遵守作者确认。

## Agent 工具

`inspiration_novel(action, payload)` 提供同一应用边界的作品/章节、设定、上下文预览、生成、查询/取消、导入/导出能力。`mutate` 需 `bookId`、`expectedRevision` 和 `operation`。

删除通过 `delete` 和 `{bookId, expectedRevision, confirmTitle}` 调用；只有作者明确要求删除指定作品、已说明不可撤销并建议 JSON 备份后才能执行。须重新读取当前作品核对名称与版本；「添加删除功能」或「验收 demo」字样本身不是删除授权。

AI 工具不能调用 `acceptProposal`、`acceptRevisionHunk`、`rejectRevisionHunk`、`acceptRevisionAll` 和 `restoreChapter`，应请作者在面板确认。`updateChapter` 是作者明确要求下的手稿编辑能力，不应被用来冒充采纳、绕过确认。工具不会执行任意文件路径或命令。后台生成返回任务编号；不要高频轮询。

## 开发与安装

- 当前目标环境：DSH **0.2.2-rc.3**。清单不放开未经验证的旧版或未来新版。升级 DSH 时须重新核对 API，不能靠跳过兼容检查来保证安全。
- 用 DSH Plugin Manager 安装此本地目录。目录安装链接源码，**不要移动/删除该目录**；不需要构建脚本或编译步骤。
- Client 是原生 ModuleLoader 插件，以 React 和正式 slots 接口挂载，不启动另一台服务器。
- 本插件未建立开发 watcher；修改源码不代表当前 GUI 立即更新。Host 缓存或替换安装的生效方式以 Plugin Manager 返回的 nextStep 为准；Client 新代码至少需要在当前 GUI 重新加载后核验。
- 自动测试：`npm test`。语法检查：`npm run check`。测试不调用收费模型；安装运行时契约的环境要求与验证边界见[测试说明](<docs/TESTING.md>)。

## 首版边界

当前是纯文本编辑器，不是富文本/排版系统。没有多人协作、任意章节重排、全文搜索/批注定位引擎、自动事实抽取、复杂伏笔依赖图、全书无人值守流水线、自动剧情正确性或文学评分保证。请把它当作可靠保留作者控制权的第一版写作工作台，而不是完整复制四个参考项目。
